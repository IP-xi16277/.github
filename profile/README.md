<p>这篇讲把海外住宅IP落到路由器上的做法。先说路由器方案适合什么场景，再讲硬件与固件的门槛，然后分别是三种接入方式的要点、按设备分流的方法、DNS 与 IPv6 两个坑，最后给一份上线检查清单。</p>
<h2>一、路由器方案解决什么</h2>
<p>把出口放在路由器上，接入的设备不用逐个配置，手机、电视、平板自动走同一条线路。</p>
<p>省掉的是重复配置，代价是所有设备共享同一个地址。它适合设备多、系统杂的场景。</p>
<p>需要每台设备用不同地址时，路由器层做不了太细，得按设备或按端口分开。这一点要先想清楚。</p>
<h2>二、硬件与固件的门槛</h2>
<p>不是所有路由器都能做。需要能填自定义网关、能改路由表、能设静态路由，或者能刷第三方固件。</p>
<p>判断方法很直接：登录后台看有没有静态路由、策略路由、DNS 自定义这几项。没有就是做不了。</p>
<p>刷第三方固件能解锁功能，但会失去保修，也可能影响稳定性。商用场景建议直接买支持策略路由的设备。</p>

<h2>三、三种接入方式的要点</h2>
<p>DHCP 最简单，插上就能用，但地址由上游决定，可能定期变化。需要固定地址时要做绑定或选静态交付。</p>
<p>PPPoE 要账号密码，注意大小写与特殊字符。拨号失败先看错误码，认证失败和链路不通是两类问题。</p>
<p>静态交付会给地址、掩码、网关、解析服务四项，缺一项就上不了网。掩码填错的表现是能通网关但出不去。</p>
<h3>双线路的取舍</h3>
<p>主备简单，一条断了切另一条；分流灵活，按目标地址走不同线路，但规则维护成本高。</p>
<h2>四、按设备分流</h2>
<p>分流的核心是给设备固定内网地址，再按地址段决定走哪条出口。常用做法是按网段做策略路由。</p>
<p>把需要走指定线路的设备集中在一段，规则里写这一段走指定网关。新增设备忘了改地址，就会走默认线路。</p>
<p>另一种是按网关分配，每台设备手动填。设备少时直观，设备多时容易漏。两种可以混用，规则要写下来。</p>
<h2>五、DNS 与 IPv6 两个坑</h2>
<p>第一个坑是解析。流量转出去了，域名解析还问本地运营商，结果与实际出口地区不一致。</p>
<p>表现为页面能开但内容按本地推送，登录地也可能被判为本地。把解析服务指向出口同地区可以解决。</p>
<p>第二个坑是 IPv6。很多线路 IPv6 直连不走代理，等于绕过了你设的出口。要么关掉，要么确认代理支持转发。</p>

<h2>六、上线检查清单</h2>
<p>前三项是出口地址、解析地区、IPv6 状态，三项都过，基础配置才算完成。</p>
<p>第四项是重启后配置是否保持，有些设备会丢规则，要确认已保存。第五项是并发设备数是否在承载范围内。</p>
<p>第六项是留一份配置备份。换设备或恢复出厂时，有备份十分钟能复原，没有就要重新摸一遍。</p>
<h2>常见问答</h2>
<h3>普通家用路由器能做吗？</h3>
<p>答：多数消费级型号缺少策略路由与自定义解析项，做不到按设备分流。整体走一条线路的场景可以尝试。</p>
<h3>必须刷固件吗？</h3>
<p>答：不一定。支持策略路由的设备开箱可用，刷固件是为了解锁功能，代价是保修与稳定性风险。</p>
<h3>改了路由器还走本地网络？</h3>
<p>答：先查解析是否跟随出口，再看 IPv6 是否绕过代理，两个都排除后再确认分流规则是否命中。</p>
<h3>多台设备会互相拖慢吗？</h3>
<p>答：会。共享同一条上行，设备越多单位带宽越少。视频类设备占用远高于网页操作，建议按用途分组。</p>
